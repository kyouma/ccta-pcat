# SPEC — спецификация кода `pfai_gen`

Подробное описание реализации, алгоритмов, кэша и предостережений для будущего
редактора. Краткая инструкция — в `README.md`.

---

## 1. Назначение

Генератор GT-примеров «скан + 2 точки → фрагмент сосуда» для задачи pFAI на
ImageCAS (КТ) и ImageCAS-X (маски просвета + центрлинии). Целевые сосуды:
**LAD (метка 2), LCx (3), RCA (9)**; LM (1) исключён (короткий, жир смешан с
аортой). Источник истины — разметка ImageCAS-X, работа на **нативной сетке**.

## 2. Структура

```
common.py       — библиотека: чтение, граф, корневание, атрибуция, радиус, NIfTI, кэш
01_cycles.py    — анализ циклов центрлиний
02_overlay.py   — наложение маски/центрлиний на КТ для ImageJ
03_qc.py        — QC и распределения
04_generate.py  — генерация фрагментов
out/            — все результаты и кэш
```

Зависимости: `numpy`, `scipy`, `networkx`, `nibabel`, `vtk`, `tifffile`,
`matplotlib`.

## 3. Данные и соглашения

| Что | Где | Формат |
|---|---|---|
| КТ | `IMAGECAS_CT/<id>.img.nii.gz` | NIfTI, HU |
| Маска сегментов | `IMAGECASX/segmentations/<id>.coronary.nii.gz` | uint8, метки 1..14 |
| Центрлинии | `IMAGECASX/centerlines/<id>.coronary_{left,right}_centerline.vtk` | legacy VTK POLYDATA |
| Сплиты | `IMAGECASX/filelist/{train,val,test,exclude}.txt` | ID построчно |

**Справочник меток** (`SEGMENT_NAMES`): 1 LM, 2 LAD, 3 LCx, 4 D1, 5 D2, 6 OM1,
7 OM2, 8 IM, 9 RCA, 10 R-PDA, 11 R-PLA, 12 L-PDA, 13 L-PLA, 14 Other. В
центрлиниях `segment_name` пишется как `LCX` (заглавные), поэтому сравнение имён
идёт через `.upper()`.

**Координаты.** VTK-точки в LPS, NIfTI — в RAS. `VTK_LPS_TO_RAS = [-1,-1,1]`
(знаки x,y). Без поправки центрлиния зеркалится относительно маски.

**Точки в VTK не упорядочены вдоль сосуда**: порядок задают ячейки `LINES`
(общий массив точек + `segment_label`/`start_points`/... поточечно). Никогда не
берите «соседей по индексу массива» для геометрии — это источник ошибок (см. п.1).

## 4. `common.py`

### 4.1 Константы

| Имя | Значение | Смысл |
|---|---|---|
| `SEED` | 42 | базовый seed |
| `TARGET_NAMES` / `TARGET_IDS` | LAD/LCx/RCA / (2,3,9) | целевые сосуды |
| `WINDOWS` | LAD/LCx `(0,40,0,40)`, RCA `(10,50,0,40)` | (A,B,C,D) мм: старт от корня, конец назад от конца |
| `MIN_FRAGMENT_MM` | 20.0 | мин. длина фрагмента |
| `SECTION_HALF_MM` | 6.0 | полуразмер цилиндра для радиуса |
| `RADIUS_SANITY` | (0.2, 3.0) | допустимый радиус, мм |
| `MAX_SNAP_MM` | 3.0 | порог ухода центрлинии от маски (QC) |
| `HU_WINDOW` | (-150, 600) | окно для серой основы overlay (контраст ~белый) |
| `GREY_GAMMA` | 1.0 | гамма серой основы (1.0 = без гамма-коррекции) |
| `PALETTE` | id→RGB | цвета меток |

### 4.2 Классы данных

- `Centerline` — scan_id, tree, points (N,3 мм), labels (N,), names, is_start/
  is_end/is_branch, cells (список массивов индексов). Свойство `roots` — индексы
  `start_points` (устье).
- `Rooted` — cl, graph, root, roots, parent, children, order, arc (dict узел→мм
  от устья). Метод `descendants(node)` — все потомки (DFS по children).
- `Attribution` — voxels (M,3), labels (M,), node (M,) глобальный индекс точки
  центрлинии, dist_mm (M,), node_points/node_labels (глобально left+right),
  offsets {tree: сдвиг}. Метод `global_nodes(tree, local)`.
- `VesselMask` — points (M,3) мировые мм вокселей одной метки, cKDTree,
  voxel_volume, zooms. Метод `section_radius(point, tangent)`.
- `PreparedScan` — scan_id, mask, affine, zooms, lines, centered, radii, attr, vms.

### 4.3 Чтение

- `read_ct`, `read_mask`, `read_centerline` (последние два — `@lru_cache`,
  возвращают **изменяемые** объекты: не мутируйте их на месте).
- `read_centerline` сам различает ASCII/BINARY VTK (через `vtkPolyDataReader`),
  читает поточечные массивы и строковый `segment_name`.
- `check_geometry` — падение при несовпадении affine КТ и маски.

### 4.4 Граф и корневание

- `build_graph` — простой неориентированный граф (вес = длина мм); схлопывает
  параллельные рёбра, годится для обхода, но не для циклов.
- `build_multigraph` — (MultiGraph, Graph) для анализа циклов.
- `root_tree` — BFS от **всех** устьев (`start_points`); `arc` =
  `multi_source_dijkstra_path_length` по весам, т.е. геодезическое расстояние от
  ближайшего устья. Несколько устьев бывают в левой системе (отдельные LAD и LCx).
- `vessel_nodes(rooted, label)` — узлы метки, отсортированные по arc, без
  недостижимых (`arc = inf`).
- `path_between(rooted, start, end)` — `nx.shortest_path` по дереву.

### 4.5 Атрибуция вокселей

`attribute_voxels` строит KD-tree по точкам обоих деревьев (в мировых мм) и для
каждого вокселя маски находит ближайшую точку. Это заменяет «скелет → граф →
атрибуция»: воксели боковых ветвей ближе к своим точкам и в целевой путь не
попадут. На проверках согласие метки вокселя и ближайшей точки — 100%.

### 4.6 Радиус

- `node_tangents(rooted)` — касательная в каждой точке по **рёбрам дерева**
  (родитель/ребёнок). На бифуркации выбирается ребёнок, наиболее коллинеарный
  входу. Дети **сортируются** — иначе результат мог бы отличаться при загрузке
  из кэша и при свежем чтении (порядок детей из BFS vs из массива).
- `VesselMask.section_radius` — оценка Кавалери: объём вокселей в тонком
  цилиндре толщины `w` вокруг точки, `A = N·V_voxel/w`, `r = √(A/π)`, медиана по
  трём `w`. Устойчива к неровной маске (в отличие от EDT в одном вокселе).
- `edt_radius_all` — один EDT на скан по объединённому просвету (`mask > 0`),
  значение в ближайшем вокселе. Union берётся, чтобы на стыках меток (LM–LAD) не
  было ложного обрыва.
- `tree_radius` — профиль радиуса по всем точкам дерева: для каждой метки своя
  `VesselMask`, касательные из `node_tangents`.

### 4.7 NIfTI и TIFF

- `save_mask_nifti` — скалярный объём с affine/spacing скана.
- `save_rgb_nifti` — RGB24. **Важно:** nibabel пишет RGB только структурным
  dtype `[('R','u1'),('G','u1'),('B','u1')]` и shape `(X,Y,Z,1)`; иначе
  `WriterError: Cannot cast to or from non-numeric types`.
- `save_rgb_tiff`, `save_labels_tiff` — multi-page TIFF для ImageJ/Fiji
  (`imagej=True`, `axes='ZYXS'/'ZYX'`, resolution в пикселях/мм, spacing z).
  Основной формат просмотра: RGB-NIfTI ImageJ/Fiji читают некорректно.
- `paint_points` — булев объём точек (опц. дилатация, чтобы линия была видна).
- `grey_from_hu` — КТ → float32 [0,1] по окну HU с гамма-коррекцией.

### 4.8 Дисковый кэш

`out/cache/<scan>.npz` (сжатый, ~0.4–0.6 МБ/скан) содержит:
маску, affine, zooms, labels_present; точки масок по меткам (`vm_<label>`);
центрлинии (points/labels/is_start/cells/edge_u,v,w/parent/arc); tangent,
radius_section, radius_edt; атрибуцию (vox/node/dist/labels).

`prepare_scan(scan_id, use_cache=True)` — при наличии файла возвращает
`_load_cache`, иначе считает и `_save_cache`. Кэш обязан быть детерминированным:
`node_tangents` сортирует детей; `arc` для недостижимых узлов пишется как NaN
(`.get(i, np.nan)` — иначе `KeyError`). Инвалидация — вручную (удалить файл или
`--no-cache`).

## 5. Скрипты

### 01_cycles.py
Строит MultiGraph/Graph по ячейкам и считает: компоненты, параллельные рёбра,
циклический ранг `E − V + C`, длины базисных циклов (`nx.cycle_basis`), длины
параллельных 2-циклов, общие рёбра. Выход: CSV + гистограммы. **Порогов нет** —
полная картина.

### 02_overlay.py
Собирает RGB-объём: серая основа КТ + полупрозрачная цветная маска
(`out = (1-α)·grey + α·color`, α=0.55) + центрлинии. Серая основа — окно
`HU_WINDOW` с гамма-коррекцией `GREY_GAMMA` (иначе скан тусклый), показывается
с фиксированным `vmin/vmax=0..1`. Центрлинии — **чёрные**. Пишет:
- `<scan>_overlay_rgb.tif` — **RGB multi-page TIFF** (`imagej=True`,
  `axes='ZYXS'`, resolution в пикселях/мм, spacing z) — основной формат для
  ImageJ/Fiji;
- `<scan>_labels.tif` — скалярные метки (ImageJ, `axes='ZYX'`);
- `<scan>_overlay_rgb.nii.gz` (RGB24), `<scan>_labels.nii.gz`, `<scan>_lut.txt`;
- PNG-проекции и README.

PNG-панели — анатомической ориентации (вертикаль S/I для сагиттальной/
корональной, A/P для аксиальной), вид обрезается по bbox маски с запасом,
aspect = spacing_row/spacing_col, сверху/справа дублирующие оси в мм.
Серый MIP строится в **приоритете по трубке**: `_tube_weight` закрашивает вокруг
каждой центрлинии мягкую сферу радиусом `TUBE_K·r` (r — EDT-радиус точки; край
`TUBE_SOFT_MM`, но не шире `0.5·R` на узел, чтобы у тонких сосудов вес в центре
доходил до 1), затем на пиксель
`proj = max(base·(1−cover), target)`, где `target` — MIP внутри трубки, а
`cover` — его проекция (гаусс `COVER_SIGMA_PX` опционален; при 0 мягкость задаёт
только `TUBE_SOFT_MM`, что согласованно влияет и на `target`). Так целевой сосуд
не перекрывается чужой кровью, а остальные структуры остаются видны. Побочный
эффект — тёмный ореол вокруг сосудов (в трубке периваскулярная ткань тёмная).
PNG — две строки: сверху сосуды (tube-MIP без разметки), снизу маски и
центрлинии. Реализация memory-friendly: uint8-объём маски, но полновоксельные
операции (~35 с/скан).

### 03_qc.py
Проверяет геометрию, согласие меток, snap (расстояние до ближайшего вокселя),
целостность дерева (компоненты, недостижимые), **оторванные компоненты без устья**
(`start_points`): в отчёте по каждому дереву выводятся число и размеры таких
компонент, а в конце — список ID проблемных сканов. Также считает радиусы сечения
против **EDT** (оба — радиусы, мм) по целевым сосудам и длины ветвей. Выход:
текстовый отчёт, CSV, PNG. `inside` трактуется как «малое расстояние до маски»,
а не пересечение.

### 04_generate.py
Для каждого сосуда:
1. `pick_start_end` — старт в `[A,B]` от корня сосуда; если окно не влезает,
   ужимается (`windows_clamped`), при `--strict-windows` сосуд пропускается.
2. Конец — среди **потомков** старта, целевая arc = `arc_tip − U(C,D)`, с
   клампом в `[start+MIN, arc_tip]`.
3. `extract_fragment` — воксели, чья ближайшая точка центрлинии в пути **и**
   метка совпадает; приёмка: непусто и ровно одна 26-компонента.
4. `make_click` — случайный воксель просвета в тонком слое сечения; ограничение
   `lateral ≤ radius`, чтобы клик был внутри просвета и окружности радиуса.
5. Радиусы берутся из кэша `tree_radius`; профиль сглаживается медианой 5.
Выход: NIfTI фрагмента, JSON, npz радиусов, points.jsonl, QC-PNG.

## 6. Параметры и как их менять

- Окна FAI: `WINDOWS` в `common.py`. Ключи — `.upper()` имени сосуда.
- Мин. длина: `MIN_FRAGMENT_MM`. Критерий приёмки — `04_generate`.
- `SECTION_HALF_MM`, `RADIUS_SANITY`, `MAX_SNAP_MM`, `HU_WINDOW` — `common.py`.
- Seed — `SEED`; локальные rng выводятся `make_rng` через `crc32` (не `hash`,
  он рандомизируется между запусками).

## 7. Детерминизм и воспроизводимость

- `make_rng(SEED, scan_id, label)` → один и тот же пример при повторном запуске.
- Касательные детерминированы (сортировка детей).
- Проверено: свежий прогон и загрузка из кэша дают одинаковые длины/воксели/сдвиги.

## 8. Особенности реализации и подводные камни

1. **Точки VTK не упорядочены вдоль сосуда.** Для касательной используйте
   `node_tangents` (по рёбрам), а не соседей по массиву. Ошибка была найдена на
   реальных данных: радиус завышался в ~1.7 раза.
2. **LPS→RAS**: не убирайте `VTK_LPS_TO_RAS`.
3. **RGB NIfTI**: только структурный dtype + shape `(X,Y,Z,1)`.
4. **Память overlay**: не строить полные float-объёмы на 3 канала.
5. **Недостижимые точки / метка 0**: бывают оторванные компоненты без
   `start_points` (например, 15 точек label 0 на скане 272). `vessel_nodes` их
   отбрасывает; `arc` в кэше может быть NaN — используйте `.get`. `03_qc`
   выводит число/размеры таких компонент и список ID проблемных сканов.
6. **Много устьев**: левая система может иметь раздельные LAD и LCx; BFS и arc —
   multi-source.
7. **Метка есть в центрлинии, но нет вокселей в маске** — проверяйте
   `label in vms` / `vms.get(label)`.
8. **Атрибуция vs подрезка плоскостями**: маска фрагмента может на доли вокселя
   выходить за концы. Если нужна строгая граница — добавить срез плоскостями ⊥
   касательной (сейчас не делается).
9. **Ужимание окон**: короткий проксимальный ствол RCA (например, 28 мм) не
   вмещает окно 10–50 мм; по умолчанию окно ужимается, в JSON `windows_clamped`.
   Для клинически строгого набора используйте `--strict-windows`.
10. **Циклы**: на `test`/`val` их нет; в `train` — 3 дерева из 1120 (5–6 мм).
    `path_between` использует кратчайший путь; при появлении циклов на целевых
    сплитах потребуется решение про MST/выбор ветви.
11. **`lru_cache`** на чтении возвращает изменяемые массивы — не мутируйте.
12. **EDT union, а не по метке**: по отдельной метке на стыке LM–LAD радиус
    ложно падает.
13. **`--no-cache`/`--strict-windows`** парсятся всеми скриптами (общий парсер),
    но читает их только 04.
14. **Центрлинии на PNG-проекциях (02)**: рисовать по ячейкам и в индексах
    вокселей (`to_voxel`). Если рисовать `cl.points` как единый массив, линия
    соединяет точки в порядке массива (он не вдоль сосуда) и превращается в
    «спагетти»-пятно; а мировые мм не совпадают с пиксельными осями фона.
    Ориентация панелей — анатомическая (`PANELS`): сагиттальная/корональная с
    вертикалью S/I (z), аксиальная с вертикалью A/P (y); при отрицательном
    диагональном элементе affine изображение и координаты центрлиний
    переворачиваются согласованно (`_orient`, `_voxel_in_view`).
    **Aspect = spacing_row/spacing_col** задаётся у ОБОИХ `imshow` (второй вызов
    без `aspect` сбрасывает его в `equal`); дублирующие оси в мм — через
    `secondary_xaxis/secondary_yaxis`. Центрлинии — чёрные без обводки; в легенде
    показываем уже смешанный с серой основой цвет, а не чистую палитру.
    Серую основу показывать с фиксированным `vmin=0, vmax=1` и гаммой — иначе
    `imshow` растягивает яркость по min/max, а мягкие ткани выглядят тускло.
    Яркость определяется ТОЛЬКО окном HU и гаммой: после наложения масок/линий
    ничего не перенормируется (в `build_overlay` приведение к uint8 идёт ДО
    смешения).
15. **Клик ограничен радиусом** (`make_click`, `limit = radius`): иначе точка
    могла оказаться вне просвета и вне окружности радиуса на QC-срезе. Слой
    вдоль касательной — полвокселя, как у радиуса.
16. **QC-срез строится по вокселям сосуда** (`_section_from_points`): растеризуем
    те же воксели, из которых выбирается клик, шагом = размер вокселя + лёгкая
    дилатация. Ресемплинг маски на сетку мог «промахнуться» мимо клика на косом
    сосуде и дать видимый выход за маску. Срез строится в **мм** (физическая
    плоскость), поэтому `aspect='equal'` корректен и spacing учитывается; панель
    маски фрагмента — MIP в мм, обрезанный по bbox (залитая, не россыпь точек).
17. **RGB-NIfTI плохо читается ImageJ/Fiji** (соляризация/битые каналы). Поэтому
    основной формат для просмотра — RGB multi-page TIFF (`save_rgb_tiff`,
    `imagej=True`, `metadata={'axes':'ZYXS',...}`; иначе tifffile принимает ось Z
    за каналы и пишет `channels=206`). Для анализа — скалярные метки TIFF/NIfTI +
    LUT.
18. **Палитра**: соседние по смыслу метки разведены по тону И яркости (D1
    ярко-оранжевый vs R-PLA светло-серый; RCA зелёный vs R-PDA тёмно-синий).
    Остальные — насыщенные различимые цвета.
19. **Одна метка может раскладываться на несколько веток/компонент**: `LINES`
    разбивают центрлинию на ячейки на каждой развилке, и у R-PDA/R-PLA бывает
    2–4 ячейки, а маска — 1–2 компоненты связности. Это нормально для ImageCAS-X,
    а не ошибка чтения; `vessel_nodes` собирает все узлы метки и сортирует по arc,
    а `path_between` соединяет их по дереву.

## 9. Производительность (ориентиры)

| Операция | Время |
|---|---|
| Чтение маски + центрлиний, атрибуция | ~1.5 с/скан |
| Радиус по сечению по всем точкам дерева | ~7–12 с/скан (первый прогон) |
| EDT объединённого просвета | ~2.5 с/скан |

## 10. Как расширять

- **Добавить сосуд**: запись в `SEGMENT_NAMES`, `WINDOWS`, при необходимости —
  в `TARGET_IDS`/`TARGET_NAMES`; ветку дерева брать по метке.

- **Подрезать концы фрагмента**: в `extract_fragment`/`04` добавить фильтр

  пути.
